# Build or improve UI

Read existing screens, shared components, tokens, and any `DESIGN.md` before choosing visual conventions. Use available design or accessibility skills when relevant; this workflow does not require a particular plugin.

- Preserve the project's visual identity. Reuse shared controls and tokens; resolve consequential design conflicts before implementation.
- Check hierarchy, product copy, keyboard use, focus, contrast, responsive layouts, and pending, empty, error, and success states.
- Inspect the changed flow at narrow and wide sizes with realistic content. Capture before/after evidence when useful; report unavailable visual checks.
- For requests for critique only, prioritize findings and leave implementation untouched.

When shared design documentation is explicitly requested, adapt [the design template](assets/DESIGN.md). Link maintained component and token sources instead of duplicating their values. Keep private plans under `.mo-stack/`. A routine UI task does not require creating a design document or installing tooling.
