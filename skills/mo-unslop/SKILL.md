# Edit writing plainly

Preserve facts, meaning, audience, and necessary technical precision. Replace vague claims with a concrete fact or remove them. Name a source for attributed claims rather than inventing one.

Remove canned praise, chatbot endings, inflated vocabulary, repetitive summaries, forced groups of three, decorative emphasis, and dense sentences that require rereading. Use familiar verbs and whole sentences with one clear point each. Keep one term for the same thing.

Preserve punctuation already present in original titles and proper names, including em dashes; do not invent new title punctuation. In body prose, use periods or commas instead of em dashes or en dashes used as sentence punctuation. Prefer plain phrasing over unnecessary hyphenation. Preserve required syntax in identifiers, model names, commands, URLs, YAML delimiters, Markdown lists and tables, and code. Do not rename a public identifier solely to polish prose unless that change is requested.

For ordinary prose, prefer straight quotes, sentence case headings, and restrained formatting. Keep exact quotations and code examples accurate. Return the edited text; edit files only when requested, and never infer permission to send or publish it.
